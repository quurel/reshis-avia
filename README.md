# Решись Авиа

Вариант C блока «Разработка»: HTML/CSS/JavaScript + Flask + MySQL. Сайт рассчитывает спрос и продажи по выбранным маршруту, дате и цене, показывает девять сценариев и поддерживает регистрацию, вход и выход.

## Что реализовано

- Форма: отправление из Москвы, одно из пяти направлений, дата с 1 июня по 1 июля 2026 года включительно, цена в рублях.
- Расчёт на Python-backend; JavaScript отправляет параметры через Fetch API. Расчёт доступен после входа.
- Всего мест, медианный спрос, прогноз продаж и свободные места по прогнозу.
- График девяти квантилей при введённой цене, отмеченная медиана и вертикальная линия вместимости. Под графиком доступна таблица всех значений.
- Регистрация, авторизация и выход. Учётные записи хранятся в MySQL, пароли — в виде хешей. Форма регистрации сразу входит в созданный аккаунт.
- Проверка входных значений, защита POST-запросов CSRF-токеном, ограничение попыток входа и регистрации, HttpOnly-сессии. Для HTTPS нужно включить COOKIE_SECURE=1.
- Адаптивное оформление, подписи полей, управление с клавиатуры и таблица как альтернатива графику.

Хостинг пока не выполнен. Инструкция для самостоятельного размещения — [TIMEWEB.md](TIMEWEB.md).

## Данные и расчёты

В `data/` лежат авторский прогноз `КручинСемёнАндреевич_my_forecast.csv` и справочник `routes.csv`. При запуске приложение читает их в память. Нейросеть заново не обучается; AutoGluon для сайта устанавливать не нужно.

Для выбранного маршрута и даты:

```text
желают = 0.5_base_demand − price_sensitivity × (цена − base_price)
купят = min(seats, max(0, желают))
свободно = seats − купят
```

Для каждой квантили используется та же формула, только вместо `0.5_base_demand` берётся её собственный прогноз. Пункт медианы на графике совпадает с карточкой спроса. График показывает точки квантилей, а не выдуманную плотность распределения. Прямые отрезки между точками служат для чтения графика.

При очень высокой цене линейная модель может давать отрицательные значения. В карточке расчётного спроса и на графике сохранён исходный результат формулы, а продажи ограничены нулём. Пояснение появляется под графиком. Это позволяет не подменять число «желают» из условия кейса. Количество продаж — прогноз и может быть дробным: это не реестр купленных билетов.

Цены `*_price` из CSV не заменяют пользовательский ввод. Расчёт ведётся при введённой цене от базового спроса. Диапазон `price_min/price_max` справочника относится к оптимизации цен в ML-части; здесь пользователь может исследовать цену от 0 до 1 000 000 ₽ с точностью до копеек.

## Локальный запуск

Нужны Python 3.10+ и MySQL 5.7+/8.0. Необязательно устанавливать Node.js: шрифт и Chart.js уже включены, сайт не зависит от CDN.

1. Распакуйте архив и откройте терминал в папке `reshis-avia`.
2. Создайте виртуальное окружение:

```bash
python -m venv .venv
```

Активируйте его на Windows:

```powershell
.venv\Scripts\Activate.ps1
```

На Linux/macOS:

```bash
source .venv/bin/activate
```

3. Установите зависимости:

```bash
python -m pip install -r requirements.txt
```

4. Скопируйте `.env.example` в `.env`. Создайте секрет командой ниже и вставьте его в поле `SECRET_KEY`:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

Укажите параметры вашей MySQL-базы в `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`. Для локального HTTP оставьте `COOKIE_SECURE=0`. Файл `.env` содержит секреты; в исходный архив и публичный репозиторий его не добавляют.

Если на компьютере уже есть MySQL, создайте пустую базу с кодировкой utf8mb4 и пользователя с правами на неё. Если вместо установки MySQL используете Docker, после заполнения `.env` можно запустить входящий в проект контейнер:

```bash
docker compose up -d --wait
```

Для этого варианта `DB_HOST=127.0.0.1`, `DB_PORT=3306`. Пользователь в `DB_USER` должен отличаться от `root`. Другой локальный MySQL не должен занимать тот же порт. Изменение пароля в `.env` после создания Docker-тома не меняет уже созданных пользователей MySQL.

5. Создайте таблицы и запустите сайт:

```bash
python -m flask --app app:create_app init-db
python -m flask --app app:create_app run
```

Откройте адрес, показанный Flask, обычно `http://127.0.0.1:5000`. Зарегистрируйте аккаунт, выберите рейс и нажмите «Рассчитать». Встроенный сервер Flask предназначен только для локального запуска; на Timeweb используется WSGI.

## Запросы backend

- `GET /` — страница прогноза.
- `GET/POST /register` — форма и создание аккаунта.
- `GET/POST /login` — форма и вход.
- `POST /logout` — выход.
- `POST /api/forecast` — JSON с `origin`, `route`, `date`, `price`. Нужны сессионная cookie и заголовок `X-CSRF-Token` из meta-тега страницы.

Пример параметров: `{"origin":"MOW","route":"MOW-AER","date":"2026-06-12","price":"9000"}`. Ответ содержит места, спрос, продажи, свободные места и девять точек `scenarios`. Ошибки возвращаются в `error`: 400 — неверные параметры/CSRF, 401 — нужен вход, 503 — база временно недоступна.

## Проверка

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Если установлен Node.js, дополнительные проверки JavaScript запускаются командой `node tests/frontend.cjs`. Они проверяют запросы Fetch, обновление карточек, совпадение медианы, авторизацию и обработку сетевой ошибки без браузера.

В автоматических тестах используется изолированная SQLite в памяти, чтобы проверить операции приложения без доступа к вашей MySQL. Обычный запуск приложения работает только с MySQL. Также проверяется компиляция схемы для диалекта MySQL. Соединение с реальной базой Timeweb нужно проверить после заполнения реквизитов и запуска `init-db`.

Проверяются регистрация, уникальность почты, хеши паролей, вход, выход, CSRF, ограничение попыток, некорректные параметры, крайние цены, все 155 рейсов и совпадение медианы с графиком. Условия и расчёты проверены автоматически; браузерная проверка в среде подготовки была недоступна из-за отсутствия сервиса предпросмотра. После локального запуска проверьте страницу и график на компьютере и телефоне.
